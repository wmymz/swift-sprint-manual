00

怎么用这份手册

你的优势是心智模型已经齐了：ARC、委托、分类、Block、GCD 这些概念你用了 8 年。Swift 的大部分概念都能在 ObjC 里找到对应物，真正的拦路虎只有三样：Optional、值类型语义、协议派发——而这三样恰好是面试最爱问的。所以这份手册的时间分配偏向它们。

每天按固定套路走三步，缺一不可：

  1. 读——按当天阅读清单读文档对应章节（链接都指向 doc.swiftgg.team，已逐条核验可访问）。先读「Swift 导览」建立全景，再钻进各章。
  2. 练——在 Xcode Playground 里手敲当天示例（File → New → Playground）。手敲不复制，肌肉记忆是面试现场白板写的底气。
  3. 测——闭卷回答当天「面试自测」题，点开答案核对要点。答不上来的，回到对应章节重读那一小节。

时长均为估计值，仅供排期参考；以「能独立讲清楚」为完成标准，不以读完为标准。

面试自测Self-check

Optional 的本质是什么？

是一个标准库泛型枚举：enum Optional<Wrapped> { case none, case some(Wrapped) }。nil 就是 .none，有值就是 .some(v)。导览的泛型一节亲手复刻过它（导览 · 泛型）。

guard let 相比 if let 的优势？

guard 强制走「条件不满足就提前退出」，把主逻辑保持在同一缩进层级；解包出的变量在 guard 之后的整个作用域可用，而 if let 只在花括号内可用。

let 和 ObjC 的 const 差在哪？

const 要求编译期常量；let 只要求「有且仅赋值一次」，右侧可以等运行期求值。原文见导览 · 简单值。

面试自测Self-check

数组赋值给另一个变量、修改其中一个，为什么互不影响？

Swift 的 Array/Dictionary/Set/String 都是值类型：赋值和传参发生拷贝（配合写时复制优化，见 Day 4）。这和 NSArray 的引用语义正好相反，是面试最经典的对比题。

switch 不写 default 什么时候合法？

当所有 case 已穷举，例如对无原始值约束的枚举逐 case 匹配、对元组按关联值穷尽匹配。编译器做穷举检查——这也是它敢去掉隐式穿透的底气。

guard 和 if let 各适合什么场景？

失败路径短、要求「不满足就离开」的场景用 guard（参数校验、解包后还要继续用）；只是局部用一下解包值的场景用 if let。

面试自测Self-check

@escaping 是什么？为什么默认非逃逸？

标注闭包可能逃出函数生命周期（存属性、异步调用）。默认非逃逸让编译器明确闭包不会活得比函数久，省去堆分配与强引用管理成本，也避免调用方无意识造成循环引用。

Swift 闭包捕获和 block 捕获的差异？

block 在创建时对局部变量做值快照；Swift 闭包默认捕获变量本身（共享同一存储），需要创建时快照要用捕获列表 [x]。值类型在捕获列表里复制，引用类型则弱/无主引用。

尾随闭包什么时候让代码更清晰？

闭包是最后一个参数且较长时（map、Task、动画 API）。闭包是唯一参数时括号都能省——导览里 sorted { $0 > $1 } 就是终极形态。

面试自测Self-check

struct 和 class 怎么选？官方标准是什么？

官方倾向默认用 struct：值语义、无继承负担、线程更安全；需要继承体系、引用身份（===）、deinit 生命周期或与 ObjC 类互操作时用 class。补充阅读：Apple：Choosing Between Structures and Classes（文档外资料）。

写时复制（Copy-on-Write）是什么？

标准库值类型（Array/String/Dictionary）赋值时并不立刻深拷贝，而是共享底层存储；任一方要写时才真正拷贝。所以「值语义」通常不意味着性能灾难。行为依据见结构体和类的值语义部分。

为什么值类型的方法改属性要标 mutating？

值类型方法里的 self 默认是 let 语义；mutating 表示「这个方法可能替换 self 的值」，编译器据此禁止在 let 常量上调用它。类方法不需要，因为类本来就是引用。

面试自测Self-check

extension 能加存储属性吗？为什么？

不能。extension 只能加计算属性和方法——它无法参与实例内存布局（存储属性决定内存大小），Swift 也没有 ObjC 关联对象那套运行时机制（不依赖 ObjC runtime 时）。加属性要求只能写成计算属性。

协议扩展的默认实现，调用时走什么派发？

变量声明为协议类型（any P）时走 witness table（协议见证表）；声明为具体类型时直接静态派发。经典坑：默认实现方法不会被「类的 vtable」覆盖——标 any 的变量看到的是协议默认实现还是类型自身实现，取决于类型自身有没有提供自己的实现。这就是「协议派发」高频题的出处：协议、不透明类型。

some 和 any 的区别？

some P（不透明类型）：调用方仍得到某个固定具体类型，编译期单一定型，无装盒开销；any P（封装协议类型/存在类型）：可装任何遵循者、运行时可换，需装箱且有动态派发开销。详见不透明类型和封装协议类型。

两段式初始化是什么？

第一段：自上而下（子类先）把自己的存储属性全部初始化；第二段：自下而上（super.init 之后）再修改继承来的属性、调用方法。这保证对象在使用任何属性前都已完整初始化——与 ObjC「先 super 再自己」的惯例正好相反，见构造过程。

面试自测Self-check

weak 和 unowned 怎么选？

对方生命周期可能短于自己（或等长关系不确定）→ weak；能证明「自己存活期间对方必然存在」→ unowned（少一次解包）。unowned 访问已释放对象等于访问悬垂指针，直接崩溃——语义上对应 ObjC 的 unsafe_unretained。出处：自动引用计数。

async/await 相比 GCD 的本质改进？

用顺序语法表达异步控制流，消除回调金字塔与「回调里丢上下文」的错误高发区；挂起点由编译器标记，取消与优先级有统一模型（Task）；actor 把「串行队列保护状态」从纪律变成类型系统约束。出处：并发。

actor 和串行队列的区别？

都是串行化访问，但 actor 是语言级隔离：编译器强制外部访问走 await，防止忘记切队列；串行队列只靠口头纪律。actor 内部可自由用同步代码访问自身状态。

defer 的执行时机？

当前作用域退出前执行，无论 return、throw 还是正常走完。典型用途：把「打开/关闭」「加锁/解锁」写在一起。见错误处理的 defer 一节。
